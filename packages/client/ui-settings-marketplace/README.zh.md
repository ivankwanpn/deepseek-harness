# @deepseek-ai/dsh-client-ui-settings-marketplace

[English](README.md) | 中文

## 概述

在 Plugins 设置里使用 **插件市场** 标签页，查看插件市场安装了哪些插件，以及每个插件当前的状态。它会列出已注册的插件市场，并为每个已安装插件显示：钉住的 commit、检测到的能力、它拥有的加载器行，以及这些行处于已启用、已停用、缺失还是不需要。该标签页在挂载时读取一次，读取失败时提供重试。它没有任何写入操作：安装、卸载与启用仍留在 `dsh plugin marketplace` 命令行上。

<a id="use-this-package"></a>
## 使用本包

打开设置里的 Plugins 区块，选择 **插件市场** 标签页。在被选中之前它不读取任何内容；选中后才挂载组件，并通过 `api-remotes` 调用一次 `ctx.remote.marketplace.status()`。

### 如何阅读一张卡片

每个已安装插件是一张卡片。标题是插件名，旁边的标签是它的状态：它拥有的每个加载器行都存在且开启时为 **已启用**；都存在且关闭时为 **已停用**；状态里有记录但补丁层没有对应行时为 **未挂载**；完全不拥有加载器行时为 **仅技能**。标签下方依次显示钉住的 commit、磁盘上检测到的能力、行 id 本身，以及内容目录。事实列表下方的来源行标明该插件来自哪个插件市场。

**仅技能** 不是故障，因此也不按故障配色。只带 skills 能力的插件不挂载任何加载器行，因为 `skill-filesystem` 是从文件系统发现的；把它称作已停用等于告诉用户一个正在生效的插件是关闭的。

### 重试失败的读取

读取失败时显示一行简短失败信息与一个 **重试** 按钮。面板不显示传输层错误码，因为可采取行动的只有重试，而错误码不会改变用户接下来做什么。

<a id="understand-the-implementation"></a>
## 理解实现

### 设计理念

**它是状态读取器，不是控制器。** 本包能提供的每个动作都是文件系统变更——抓取仓库、写入插件目录、重写补丁层——而那些属于命令行：它在用户自己的机器上以用户自己的权限运行。由浏览器发起的安装需要一套权限模型、一个确认步骤，以及一套部分失败的交代方式，而这三者目前都不存在。所以这个界面只读，并通过「没有任何写入按钮」来表明这一点。

**不缓存任何东西。** 主机端每次调用都读取状态档并解析补丁层。两者都会在 harness 运行期间改变：命令行可以在浏览器开着的时候安装或停用某个插件，Cordis HMR 也可以随时重写补丁层。缓存的快照需要为每个写入方准备一条失效路径，而这次读取足够便宜，根本不需要。

### 主机端读取的保证

主机端的 `status()` 从不落地。`materializeEntry` 会把 skills 复制进发现根目录，还可能把它们停放到 `.disabled` 下，因此以它为底的读取会因为打开一个设置标签页而顺带改动用户的磁盘。行 id 改为从每个已安装插件的 `.mcp.json` 推导，这与写入方的推导相同，所以两者一致，而双方都没有写入。

启用状态只来自补丁层，与插件市场套件所声明的归属规则一致：存在性与来源在状态档，启用状态在补丁层。「它开着吗」只有一个答案，而这次读取报告的就是它本身，不是副本。

<a id="model-experience"></a>
## 模型体验

### 插件市场面板

#### 模型看到什么

什么都没有。该面板是给人类操作者用的设置界面：它没有任何部分进入系统提示词、工具区块或消息流，模型也无法读取或调用它。面板所**报告**的内容——插件的安装路径、钉住的 commit 与行 id——描述的是别处挂载了什么，而任何真正到达模型的东西都是经由那些已挂载的行与被发现的 skills，而不是经由这个标签页：一个 MCP 行表现为 `mcp__<serverName>__<tool>` 形式的工具，一个被发现的 skill 则表现为一行目录，模型通过 `skill` 工具取得它。

#### Token 影响

零。本包没有任何贡献被加入请求，面板自身的文字也只在人类打开该标签页时才渲染。

#### KV Cache 影响

无。打开、读取或关闭面板都不会改变请求前缀中的任何内容，因此没有缓存边界会移动。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- **它只读，不能动作。** 安装、卸载、启用与停用都只在命令行。由浏览器发起的写入需要一套本包尚未具备的权限与确认机制。
- **读取失败不做诊断。** 面板显示一个笼统的失败与重试，因为主机端的错误文本是文件系统或解析层面的诊断，需要操作者在终端里解决。
- **两个区块是列表，不是搜索。** 有数百个插件的插件市场请从命令行浏览；这个标签页要回答的是「我装了什么，它开着吗」，而不是「我能装什么」。
- **没有更新或版本视图。** 面板显示钉住的 commit，但不显示插件市场现在是否列了更新的版本，因为本包没有任何东西会去解析上游 revision。

<a id="dev-note"></a>
### 开发备注

这里有两个决定是被建置逼出来的、不是选出来的，两者都记录下来，否则下一个人会再痛苦地发现一次：

- 主机端 `status()` 的返回类型会经由产生出来的 Remote 声明抵达**浏览器**编译面。早先的版本从 gateway 模组再导出线缆契约，这让前端建置去解析该模组，进而为一个浏览器目标编译整个 Node 侧套件——`node:fs`、`node:url` 全都在内。因此契约只住在 `types.ts`，而 gateway 只 import 它、不再导出。
- 同一个限制也移除了对 `@deepseek-ai/dsh-app-boot` 的 `PROFILE_PATCH_FILENAME` 的 import，因为那是 Node 专属的。改用字面值，并以注释指名真正拥有该常数的套件。
