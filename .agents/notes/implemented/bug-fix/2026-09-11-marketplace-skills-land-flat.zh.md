# Agent Note: Marketplace skills land flat in the discovery root

Status: implemented

[English](2026-09-11-marketplace-skills-land-flat.md) | 中文

## 问题

marketplace 把插件的 `skills/` 子树复制进一个按插件隔离的目录 `<root>/<plugin>/`。而 `skill-filesystem` 恰好只读一层——`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`——因此落地后的文件比任何东西会发现的位置都深了一层。于是只带 skill 的插件「安装成功」：`install` 打印出钉住的 commit，状态记录下 `skills` 能力，设置面板把插件列为已安装，而模型一个 skill 都拿不到。没有任何东西失败，也没有任何东西报告问题。

卸载有镜像的缺口。落地后的 skill 按设计位于共享根目录，而不是 `installPath` 之下，而 `uninstallPlugin` 只删除插件目录与记录——于是被移除的插件仍在被提供给模型，且没有任何记录能解释这些文件从何而来。

## 决策

插件的 `skills/` 子项被**平铺**落地：每个子项成为发现根目录正下方的一个条目，且只以发现能读取的形态出现。

- **可发现性决定复制什么。** 子目录必须在顶层持有 `SKILL.md`；子文件必须是 Markdown。其他一切都会被报告并跳过，而不是复制进一个它注定不可见的根目录。
- **拥有关系被记录，而非重算。** 状态条目携带 `skillIds`，即该插件拥有的发现根目录条目名，与 `rowIds` 平行。一个插件贡献多个条目，而具体是哪些并不是插件名称的函数。
- **一个动词，两种布局。** `disable` 把拥有的每个条目停放到 `<root>/.disabled/<plugin>/`；`enable` 把它们移回；卸载会连同更早的构建写下的按插件隔离容器一起，删除它们（存活态与停放态）。
- **平铺的根目录让重名成为真实冲突。** 状态顺序中靠前的条目保留该名称；靠后声称拥有它的插件会被报告，且不在该名称下落地任何内容，因此任何一方都无法替换对方的 skill，或在卸载时删掉它。
- **在 `skillIds` 存在之前写下的记录仍然可用。** 启用、停用与卸载会在插件目录仍然存在时从中恢复这些名称，下一次 sync 会把它们持久化。

## 备选方案

**让 `skill-filesystem` 多读一层。** 拒绝：那个 provider 同时服务与 marketplace 毫无关系的项目根目录与用户根目录，而多读一层会把 skill 的每个子目录都当成候选 skill——正是暴露此 bug 的那个插件里的 `brainstorming/scripts` 与 `brainstorming/assets`。为修一个写入方的布局而放宽共享扫描器，只是把缺陷挪了位置，没有消除它。

**在按插件隔离的目录下为每个 skill 合成一个 Markdown 文件（`<root>/<plugin>/<skill>.md`）。** 拒绝：那是用「改写插件内容」的方式表达平铺形态。skill 目录里存放着正文以相对路径引用的同级资源，把它压成单个文件恰恰丢掉了让该 skill 可用的材料。

**在启用与卸载时从插件目录重算拥有的名称，而不是记录它们。** 拒绝：这与本包已为 `rowIds` 确立的拥有规则相矛盾，并且在两个真正要紧的场景下失效——自上次 sync 以来磁盘内容已改变，以及卸载，此时必须在名称所属的目录被删除之前读取它们。

**报告重名的 skill，但允许靠后的插件覆盖它。** 拒绝：覆盖是静默的，而且先被卸载的那一方随后会删掉另一方仍然声称拥有的内容。

## 后果

skill 现在能到达模型，启用、停用与卸载都精确针对已落地的东西。两处静默失效变成了会被报告的问题：发现读不了的 `skills/` 子项会在 sync 时被点名，重名的条目会同时点名两个插件。

代价是发现根目录不再是「一个插件一个目录」。卸载变成按记录寻址的 N 次删除，而不是一次 `rm`，而且它现在会删除 `installPath` 之外的内容，因此那里的文件系统失败不再被一个看起来成功的命令掩盖。状态文件新增了可选的 `skillIds` 字段，更早的记录会省略它，并由下一次 sync 填入。

## 测试

`tests/skills.spec.ts` 在落地后的根目录上挂载真实的 `dsh-skill` 注册表与 `dsh-skill-filesystem` provider，并针对该 provider 实际发现了什么来断言，而不是把布局规则复述成可能与之漂移的路径字面量。落地断言已确认对按插件隔离的复制会失败；任何只针对目标目录本身的断言都抓不到它。
